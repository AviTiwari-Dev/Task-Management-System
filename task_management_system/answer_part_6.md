To handle 1 million requests per day, the system should be deployed as independently scalable microservices behind a load balancer (such as NGINX or a cloud load balancer) that distributes incoming traffic across multiple instances of the Auth Service and Task Service. Container orchestration platforms like Docker and Kubernetes can automatically scale service instances based on CPU, memory, or request volume. The PostgreSQL database should be configured with primary-replica replication, where the primary node handles all write operations and one or more read replicas serve read-heavy requests. If the dataset or traffic grows significantly, database sharding can be introduced by partitioning data (for example, by user ID) across multiple database servers to distribute storage and query load.

To reduce database load and improve response times, Redis should be used as a caching layer for frequently accessed data such as user profiles, task lists, role and permission information, and JWT validation metadata. Frequently requested API responses can also be cached with appropriate expiration policies. For observability, centralized logging should be implemented using the ELK Stack (Elasticsearch, Logstash, Kibana) or Grafana Loki, while Prometheus and Grafana can collect and visualize metrics such as request rate, latency, CPU and memory utilization, database performance, and error rates.
